System Architecture

Blog & Portfolio (Static, Zero-Cost)

1. Mục tiêu & ràng buộc thiết kế

Ràng buộc

Mô tả

Chi phí

Không dùng dịch vụ trả phí (hosting, CMS, database)

Sở hữu dữ liệu

Toàn bộ nội dung nằm trong Git repo, không phụ thuộc nền tảng thứ ba

Portable

Có thể rebuild toàn bộ site ở bất kỳ máy nào chỉ với git clone

Hiệu năng

Tải trang nhanh, SEO tốt, không cold start

Nội dung

Viết bằng Markdown, hỗ trợ cả bài blog và case-study dự án (portfolio)

Vận hành

Tự động hoá build/deploy, có giám sát uptime và theo dõi lượt xem

Nguyên lý cốt lõi: Mọi thứ bắt đầu và kết thúc ở Git. Không có backend runtime, không database — toàn bộ site được build sẵn thành file tĩnh (Static Site Generation).

Đặc điểm: luồng dữ liệu một chiều, không có vòng lặp runtime nào phụ thuộc server. Analytics và monitoring chạy song song, không chặn pipeline chính.

Lý do tách 2 collection riêng trong Decap CMS: blog và project có field khác nhau (project cần nhiều metadata có cấu trúc hơn: link, tech stack, ảnh cover), nên định nghĩa 2 collection độc lập trong admin/config.yml thay vì dùng chung 1 schema.

5. Luồng vận hành (Data flow)

Author viết nội dung qua Decap CMS (chạy tại /admin, xác thực qua GitHub OAuth) hoặc chỉnh trực tiếp file .md.

Decap commit file Markdown mới/sửa vào nhánh master của repo.

GitHub Actions trigger khi có push vào master: checkout code, cài dependencies (npm ci), chạy next build.

Next.js gọi generateStaticParams() cho cả blog/[slug] và projects/[slug], đọc toàn bộ file trong content/.

remark parse Markdown → AST → HTML; rehype-highlight tô màu code block. Output ra thư mục ./out.

Deploy thư mục ./out lên GitHub Pages qua actions/deploy-pages@v4.

User truy cập — chỉ nhận file HTML/CSS/JS tĩnh, không có request nào chạm tới server logic.

Song song: PostHog script ghi nhận pageview; một GitHub Action riêng (cron hàng tuần) pull thống kê về, lưu JSON dùng cho lần build kế tiếp.

Song song: Uptime Robot ping site mỗi vài phút, gửi cảnh báo nếu downtime.

8. Bảo mật

Không có input người dùng nào được render trực tiếp lên trang (nội dung do chính tác giả kiểm soát qua Git) → rủi ro XSS gần như bằng 0 dù dùng dangerouslySetInnerHTML.

Pipeline remark → rehype tự escape HTML tag lạ trong Markdown.

Form liên hệ nên dùng dịch vụ ngoài có sẵn spam-protection (reCAPTCHA/honeypot) thay vì tự xây.

GitHub Actions dùng GITHUB_TOKEN mặc định, không cần lộ secret nào ra ngoài.

10. Lộ trình triển khai (Deployment roadmap)

Giai đoạn 1 — Nền tảng

Khởi tạo repo Next.js, cấu hình output: 'export'

Viết lib/posts.js và lib/projects.js (đọc file, parse frontmatter)

Dựng route blog/[slug] và projects/[slug] với generateStaticParams

Giai đoạn 2 — Content Management

Cài đặt Decap CMS tại /admin, cấu hình 2 collection (posts, projects) trong config.yml

Thiết lập GitHub OAuth cho Decap

Giai đoạn 3 — CI/CD

Viết workflow deploy.yml, kiểm tra GitHub Actions build & deploy thành công

Bật GitHub Pages, trỏ custom domain (nếu có)

Giai đoạn 4 — Vận hành

Tích hợp PostHog script + GitHub Action pull thống kê hàng tuần

Đăng ký Uptime Robot, thiết lập public status page

Gắn form liên hệ qua Formspree/Getform

Giai đoạn 5 — Hoàn thiện

Tối ưu ảnh, SEO metadata (<meta>, sitemap.xml, robots.txt)

Viết bài blog đầu tiên ghi lại chính quá trình xây dựng hệ thống này
